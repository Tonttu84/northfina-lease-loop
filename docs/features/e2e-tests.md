# Browser tests: the pitch run clicked through with Playwright

## What it does

`npm run test:e2e` builds the app, starts it the way the pitch does (`next start`, the demo tools on) against its own SQLite file, and drives a real Chromium through the demo script: the Run buttons, the actor picker, the second-life page, the signing link, the language switch, the audit badges with the tamper script, the catalogue filters and the locale routing. It is the one layer the Vitest suite could not reach: the pages and the client components as a user clicks them, with the cookies, the proxy and the server components in between.

## The rule

- **A built app, not the dev server.** The web server is `next start` on port 3100 (after `scripts/ensure-env.mjs`, so `.env` holds the audit key and the session secret, D92), with `DATABASE_URL=file:./e2e.db`, `DEMO_TOOLS=1` (the Run buttons are off in a production build otherwise, D74) and `AUDIT_ANCHOR_FILE=''` (the anchors beside `e2e.db`). That database environment is written once, in `e2e/env.ts`, and the spec process puts it in its own `process.env` too: it reads the shell, not `.env`, so an `AUDIT_ANCHOR_FILE` a developer exported for `dev.db` is never the file the reset deletes. Next and `prisma.config.ts` never overwrite a variable already in the environment, so these win over `.env`; the signing key still comes from `.env`, which `npm run db:setup` (or `npm run setup`) creates. Locally the run builds first; in CI the Build step already did, and `E2E_SKIP_BUILD=1` does the same by hand.
- **One database per run, one fresh database per test.** `e2e/prepare-db.mjs` removes `e2e.db` and its anchor file and runs the real migrations before the server opens the file: it is the first part of the web server command, because Playwright starts the web server before `globalSetup` runs. Before every test the `db` fixture empties the database with the Vitest suite's `resetDb` (D44 rule 1) and reseeds it by running `prisma/seed.ts` under tsx, as `prisma db seed` does, then moves the seeded company signatories to 2026-01-01: the seed puts them on the real day, which is after every card's day now, so on the demo clock they would read as not yet valid (the polish review's bug 10). The spec process is plain Node and imports nothing from the server slices: their `authorize` → `actor` chain reaches `next/headers`, which only exists inside Next, so the seed runs as a child process (two to three seconds a test). The server is the other connection to the same file; it holds no data in memory, so the reset needs no restart.
- **One worker, files in order, no retries.** Every spec writes to the one file and the one audit chain, so `workers: 1`, `fullyParallel: false`, `retries: 0`: a flaky spec is a bug. The whole run has a cap (`globalTimeout` 15 minutes, every test 60 seconds, every expectation 5 seconds; AGENTS.md rule 11). A failure keeps its trace and screenshot under `test-results/`; CI uploads them with the HTML report.
- **The run is waited for, the buttons are live.** `runCard(page, n)` clicks a Run button and waits for the answer of `POST /api/demo/cards/n/run` and for the button to be enabled again: the run (the quote, the application, the signing, 36 invoices, the signed audit rows) can take longer than one expectation's five seconds on a slow runner, which made the specs flake twice in the review of PR #6. The buttons that post with `fetch` (Run, the actor picker's Continue and Stop, Assess and relist, Sign and Decline) are disabled in the server HTML until React has hydrated the page (`src/components/use-hydrated.ts`, the gate the Run button had alone), so a click waits for a live button instead of hitting a dead one, and the actor picker's form can no longer submit itself as a native GET.
- **Cookies through the real routes.** `actAs(actor)` posts to `/api/actor` (or deletes), `travelTo(day)` posts to `/api/demo/clock`, both into the page's own cookie jar; nothing is forged. Each test has a fresh browser context: nobody is chosen and the clock is on the real day until a spec says otherwise. The Run buttons set both themselves (D71).
- **Money as the page writes it.** `money('107,30 €')` is a regular expression that accepts the no-break space Finnish, Swedish and Estonian put before the sign.

**Worked example, card 1.** On a fresh database the spec opens `/en/demo`, clicks "Run card 1", reads the steps the button lists ("Quoted ebike-003 for 36 months with €0.00 down on 5 November 2026: €107.30 a month without VAT, price list 1", "Applied …: Yes, you can lease it", "Signed contract LL-…"), follows "Open the page to compare" to `/en/contracts/<id>` and checks `€107.30` (the net 10 730 of band B, factor 0.027584), `€134.66` exactly twice (November and December 2026 at 25.5 %), `€135.20` exactly 34 times (January 2027 on, at 26 %: the other invoices of the 36) and the VAT-change line; the header now offers "My leases", because the run set the actor to Aino. Clicked again, the button shows "Card 1 has already run" and "Open what the first run made" points at the same contract (D70). In Finnish (`/fi/contracts/<id>?from=leases` after the header's "Suomi") the same page writes `107,30 €`, `134,66 €` twice and `135,20 €` 34 times, and the query survives the switch.

## Decisions

- **D91** browser tests of the pitch run with Playwright on the built app, one worker, reset and reseed per test, the actor and the clock through the real routes (this page).
- **D44** test isolation by reset: the fixture reuses `resetDb` and the seed script.
- **D70, D71** a second click is refused and links the first run; a run sets the clock and the actor; the specs lean on both.
- **D74** the demo tools are a switch: `DEMO_TOOLS=1` is mandatory for the server under test.
- **D46, D85** the signing link and the back-office page: what the card 6 and second-life specs prove end to end.

## Pure functions

Test code, no domain code. The fixtures (`e2e/fixtures.ts`):

- `test`: Playwright's `test` with `db` (automatic: resets and seeds before every test, the Prisma client on `e2e.db`), `actAs(actor | null)` and `travelTo(day | null)`.
- `money(text): RegExp`: the money string with every space allowed to be a no-break or narrow no-break space, the rest escaped.
- `runCard(page, cardId): Promise<void>`: clicks the card's Run button and waits for the run route's answer and for the button to be enabled again, 30 seconds at most each.
- `tamperAuditLog(): void`: runs `scripts/tamper-audit.mjs` with `tsx` against `e2e.db`, as `npm run demo:tamper` does, with a one-minute limit.
- `SIGNATORIES_VALID_FROM`: `2026-01-01`, the seeded mandates' first day.

## Files

- `playwright.config.ts`: the runner, the browser, the web server and its environment.
- `e2e/env.ts`: the test database's environment (`DATABASE_URL`, the empty `AUDIT_ANCHOR_FILE`) once, for the config, the fixtures and the scripts they run.
- `e2e/prepare-db.mjs`: the fresh `e2e.db` before the server starts (refuses any `DATABASE_URL` that is not an e2e file).
- `e2e/fixtures.ts`: the fixtures above.
- `e2e/01-card-1-happy-path.spec.ts`, `02-actor-picker`, `03-second-life`, `04-card-6-signing-link`, `05-language-switch`, `06-audit-page`, `07-catalogue-filters`, `08-locale-routing`: the eight specs, in the pitch's value order.
- `package.json`: `test:e2e`, `test:e2e:ui`, `test:e2e:report`; `@playwright/test` pinned exact. `check:all` and the pre-push hook stay Vitest-only: the browser run needs a build and a browser.
- `vitest.config.ts`: the server project excludes `e2e/**`. The meta rules scan `src/` and `tests/`, the file-size check skips `*.spec.ts`, `check:no-ai` scans `src/` and `prisma/`.
- `.github/workflows/ci.yml`: after Build, the browser cached on the `@playwright/test` version (`actions/cache`; another dependency bump keeps the cache), `npx playwright install --with-deps chromium` on a miss, `npm run test:e2e` with `DEMO_TOOLS=1`, the report and traces uploaded on failure.
- `src/components/use-hydrated.ts`: the hydration gate the Run, Continue, Assess and Sign buttons share.
- `docs/features/STATUS.md`: the slice's row, under "After the hackathon".
- `.gitignore`, `.prettierignore`, `eslint.config.mjs`: `test-results/`, `playwright-report/`, `blob-report/`; `e2e.db*` and the anchor file were already ignored.

## Open questions

- **The other eight cards.** Cards 2, 3, 4, 5, 7, 8, 9 and 10 run from the demo page only in `src/server/demo-cards.test.ts`; a browser spec per card would repeat the pattern of card 1 (the Run button, the landing page, the one number the presenter points at).
- **A phone width.** The demo script narrows the window to 375 px; a mobile project (`devices['Pixel 7']`) would check the stacked layout and the menu.
- **The Vitest wins the review listed alongside** (`src/app/api/actor/route.test.ts`, `src/proxy.test.ts`, an i18n used-keys test, `resetDb` in the demo-run route test) are not in this branch.
- **`npm run test:e2e` locally builds every time.** `E2E_SKIP_BUILD=1` reuses `.next/`; a stale build then tests stale pages, which is why the default rebuilds.
